# 设计决策与取舍

## ADR-001：先稳定 Agent 闭环，默认离线 mock

目标是让读者无需权限或密钥就能验证状态管理、证据绑定、审批与反馈循环。选择 Python 标准库、确定性 mock planner 与概率模拟执行器，源码直接运行。真实 LLM 的语言理解、工具选择、延迟和 token 成本均未评估。

代价：规则只能识别示例的 key=value 遥测，无法从一般自然语言自动重建任意 BugContext；三种机制与实验阶梯都由人工编写。这个模块叫 MockPlanner，避免把模板匹配包装成模型能力。

## ADR-002：证据先于流畅解释

只提取可绑定字符区间的信号，原文保持不变。报告把“来源中记录了某信号”与“该机制成立”分开。没有证据的机制不生成候选，环境缺口直接阻断。

代价：保守拒答会增加人工介入。证据字符串可追溯不等于语义正确；错误日志、过期版本、伪造群聊仍然可能误导规划。当前排序没有来源可信度权重，`mixed_clues` 展示了这个缺点。

## ADR-003：显式状态机与本地事件，而非先引入编排框架

工作流只有提案、决定、执行三个事件。把转换限制放在应用层，便于测试未授权执行、重复事件、审批过期与版本漂移。暂不引入数据库、队列、图编排框架或跨进程恢复服务。

代价：本地锁只适用于单机文件系统；进程异常可能留下 `.lock`，需要确认没有活跃写入者后人工清理。不保证断电后目录元数据持久性，不提供分布式 exactly-once，也没有身份认证。将来接外部执行器时需要持久化租约、幂等执行 ID 和真实权限控制。

## ADR-004：审批批准一个确定实验

actor、reason、决定与完整提案 SHA-256 一起保存。审批后代码、模拟器、策略或上下文变化会阻止执行。迭代产生新实验，必须重新决定。demo / evaluation 的自动审批明确标注为脚本行为。

代价：修改任何模块都会使旧实验无法在新代码下直接执行或重放。优先选择可审计性，避免在演示中默许代码漂移。哈希链只能发现未重算摘要的修改，无法防止有写权限的人重写整个历史；actor 也是自报字符串。

## ADR-005：先 CLI 与 Markdown 报告

读者能用几条命令运行流程，直接在 GitHub 审阅数据、报告和代码。无需前端构建、数据库或部署服务；不把 UI 完整度当作工程闭环的替代品。

代价：目前的“工作台”是命令行和实验文件，不是多用户 Web 产品。后续可在同一 workflow 层上增加本地界面，不应在页面中重写审批状态机。

## ADR-006：评测同时保留成功与失败

使用普通重试、固定第一策略消融和完整迭代，共享相同每轮 seed 和最大尝试次数。保留所有失败与阻断，报告成本以及逐案例分母。模拟器与预期阻断标签只由执行器 / 评测器读取。

代价：所有案例和阈值均由项目作者构造，heldout 只是场景迁移检查，不能证明真实泛化。使用共同随机数降低对比噪声，也让案例间结果存在相关性；不把它当作真实独立样本进行显著性结论。

## 可选真实模型适配器：替换边界，不是已完成功能

`Planner` 协议是后续接入点。当前 workflow 与 replay 固定使用 MockPlanner，**仅实现协议还不足以启用新模型**，还需要：

1. 加入显式 provider 选择与适配器注册，不允许缺少配置时自动发送上下文。
2. 模型只接收审核过的 BugContext / history；原始材料、标签与模拟器真值不进入请求。
3. 对响应做严格 schema、来源引用与参数白名单校验；缺失证据时返回待澄清，不能退化成任意命令。
4. 保存 prompt / 响应摘要、模型版本、采样参数与调用成本；重放使用记录的响应，而非重新调用不确定模型。
5. 拆分普通执行与离线评测，加入真实模型的无依据断言、提示注入、成本和超时测试。

本项目没有实现 provider、SDK 或密钥管理。所有现有命令都不会读取环境中的模型密钥。若以后接真实系统，需要另行设计权限、数据外发策略与真实工具沙箱。
