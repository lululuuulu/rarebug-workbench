# 5 分钟项目演示与面试说明

## 0:00—1:00：问题与边界

“低概率问题常见的困难是上下文散落、复现实验缺少依据，以及多次尝试后没有可复用反馈。我做了一个完全合成数据的 Python MVP，展示从线索到有预算实验、人工审批、执行反馈和可重放快照的闭环。当前推理是 deterministic mock，执行是概率模拟器，不是生产环境的自动根因分析。”

## 1:00—2:30：现场运行

```sh
python3 -m rarebug demo --scripted-approvals --out runs/interview
```

打开报告，指出逐字证据 span、observed 与 reported 的差别、假设未验证状态。展示第一轮 20 次未命中、第二轮升级参数后命中。说明示例审批来自脚本；手动模式会卡在 pending_review，执行命令不会默认批准。

再运行不带脚本审批的 demo，或使用缺失环境案例创建 plan，展示系统如何拒绝继续。用相同目录重复实验会因不覆盖策略而失败，需要新目录。

## 2:30—3:30：工程取舍

选择一两个点深入解释，而非罗列组件：

- 为什么审批绑定方案摘要：历史审批不应该授权一个已经改变的实验。
- 为什么把假设与事实分开：来源中出现线索只支持探索，不证明根因。
- 为什么快照同时记录代码和 Python：相同 seed 并不足以说明整个系统可复现。
- 为什么 mock 足以验证某些工程能力：状态、权限与审计可以先建立可测试约束；模型理解能力必须另测。

## 3:30—4:30：失败和评测

打开评测报告。先讲分母、共享预算和成本，再讲结果。主动展示 `mixed_clues`：群聊猜测导致策略分流、整体 heldout 成功率 85/120，成本高于普通重试。解释“可引用”与“可信”之间还差来源权重、相互矛盾信息处理和实验信息增益。

## 4:30—5:00：下一步实验

给出可检验的改动，而不是只说接大模型：冻结新排序规则，加入独立新案例，比较等成本预算下的成功率与错误方向消耗；之后再接模型适配器，增加无依据断言和提示注入评测。

## 常见追问

**“这算 Agent 吗？”** 它实现了受约束的 observe → plan → act → feedback 循环，以及人工决策和持久状态；当前规划器是规则 mock，所以没有证明 LLM Agent 的理解或自主推理能力。

**“为什么不直接用图编排框架？”** 当前状态机很小，标准库实现更易审阅与离线复现。复杂分支、恢复与多工具并发出现后再评估框架；不靠框架名称证明设计能力。

**“真实执行怎么办？”** 需要另建安全的动作注册、权限、超时、取消、幂等与恢复机制；绝不能把模型字符串交给 shell。当前范围只执行模拟参数。

**“如何验证模型没有编造？”** 本版验证引用存在与 span 匹配，并限制策略参数；语义真实性、错误引文和模型响应不确定性要另外做标注评测，不能用现有 span 指标替代。
